# Software architecture

1. Establish business goals, quality attributes, constraints, scale, team topology, and failure tolerance.
2. Model contexts, responsibilities, data ownership, dependencies, and trust boundaries.
3. Prefer the simplest architecture that meets current requirements and leaves reversible seams.
4. Make consistency, availability, latency, security, and operational trade-offs explicit.
5. Design failure containment, observability, deployment, migration, and rollback from the start.
6. Record consequential decisions with context, options, decision, consequences, and review date.
