# GitHub

1. Confirm repository, branch, issue or pull request, and requested scope.
2. Inspect metadata, changed files, review state, checks, and linked work before acting.
3. Keep PRs focused and explain problem, solution, validation, risks, and rollout.
4. Address review feedback with code evidence and avoid resolving threads before the fix is verified.
5. Use least-privilege automation and pin third-party Actions to trusted immutable versions.
6. Do not merge, publish releases, or change repository settings without explicit authorization.
