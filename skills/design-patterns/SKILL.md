# Design patterns

1. Describe the concrete forces, variation points, coupling, and failure modes before naming a pattern.
2. Prefer language features and simple composition when they solve the problem directly.
3. Apply the smallest pattern that removes demonstrated duplication or instability.
4. Keep abstractions aligned with domain language and dependencies explicit.
5. Document why the pattern exists and what change it is intended to absorb.
6. Test through public behavior so implementations remain replaceable.
