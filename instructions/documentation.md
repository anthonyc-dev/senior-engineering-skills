# Documentation

- Document decisions, contracts, setup, and non-obvious operational behavior.
- Keep examples executable and synchronized with the implementation.
- Prefer concise task-oriented guidance over duplicated code commentary.
- Update related documentation in the same change as behavior.
- Compare installation instructions against the installer and manifests, API docs against routes and contracts, and database docs against migrations and schema. Check architecture notes and decision records against current boundaries. Cite mismatches and update affected docs only when authorized.
- Validate links and example commands using disposable fixtures or read-only checks when possible. Record example execution gaps and leave undocumented or ambiguous behavior flagged for verification.
- Never include live credentials, private endpoints, or personal data.
