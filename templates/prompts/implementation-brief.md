# Implementation brief

## Requested outcome

State the observable behavior to add or fix, who uses it, and concrete acceptance examples. For a bug, include the exact failing request, payload, or reproduction with secrets removed.

## Repository context

Name the relevant feature/files and established architectural boundaries. Ask the agent to read nearest project instructions and configured validation commands before editing. Identify any unrelated work that must be preserved.

## Scope and compatibility

Specify required callers, UI/API surfaces, role/tenant boundaries, data invariants, backward compatibility, and exclusions. Require the smallest complete change using existing patterns and dependencies.

## Risk and authorization

Describe migrations, external side effects, paid requests, and production access. Distinguish authorized local work from actions needing separate approval. Never paste credentials into this brief.

## Required evidence

Require focused behavior tests and configured broader checks appropriate to risk. Ask for actual commands/outcomes and explicit not-run reasons. For reported failures, require verification through the same entry point after the fix.

## Handoff

Request changed files, root cause or design rationale, test evidence, remaining risks, and necessary next action. Acknowledge unavailable execution rather than accepting fabricated passing results.
